## Chunk 1 — Dedup on write (cosine ≥ 0.88)

### Goal
Before inserting a new memory, check if a near-identical memory already exists
for the same `(user_id, category)`. If cosine similarity > 0.88, skip the
insert and bump `seen_count` + `last_referenced` on the existing row.

### Why
- Today: `resolveConflicts` uses word-overlap (≥0.95 = duplicate). Misses
  paraphrases ("takes Tamoxifen 20mg" vs "is on tamoxifen 20mg daily").
- Cosine on embeddings catches semantic dupes that word-overlap misses.
- `seen_count` already feeds retrieval ranking — bumping it lets repeated
  facts naturally rise.

### Constraints
- **Mandatory user-id scoping** (no cross-patient merges) — query MUST filter `user_id = $1`.
- **Mandatory category scoping** — different categories never dedupe (a `medication` fact must not collide with a `lab_result` fact even if cosine is high).
- **Strict `>` not `>=`** at 0.88 threshold (so a tie at 0.88 inserts a new row, preserving the original behavior in the edge case).
- Falls back to existing word-overlap logic when no embedding available.

### Write path (today)
`extractAndSaveMemories` in `apps/web/src/lib/memory/extract.ts`:
1. Extract facts (Haiku structured output)
2. Filter instruction-shaped (poisoning defense)
3. `resolveConflicts` (word-overlap dedup + supersession)
4. Embed batch
5. INSERT row

### Write path (after chunk 1)
1. Extract facts
2. Filter instruction-shaped
3. Embed batch
4. **NEW:** `findCosineDuplicate(userId, category, embedding)` per fact
   - If dup → `UPDATE memories SET seen_count = seen_count + 1, last_referenced = NOW() WHERE id = $dupId`; skip insert
5. `resolveConflicts` on remaining (word-overlap still catches non-embedding cases)
6. INSERT remaining rows

### File touchpoints
- `apps/web/src/lib/memory-conflict.ts` — add `findCosineDuplicate(userId, category, embeddingLit): Promise<{ duplicateId: string | null }>`
- `apps/web/src/lib/memory/extract.ts` — insert cosine-dedup step between embed and resolveConflicts
- `apps/web/src/lib/__tests__/memory-conflict.test.ts` — new tests (RED)

### TDD: tests first

| 1 | Same user, same category, cosine 0.95 → `findCosineDuplicate` returns existing id | `{ duplicateId: <uuid> }` |
| 2 | Same user, same category, cosine 0.88 (exact threshold) | `{ duplicateId: null }` (strict `>`) |
| 3 | Same user, same category, cosine 0.87 → no dup | `{ duplicateId: null }` |

## Chunk 2 — Decay TTL job

### Goal
Soft-delete memories whose `decay_at < NOW()` via daily cron, by setting `valid_to = NOW()`. Retrieval already filters `valid_to IS NULL`, so this transparently removes stale memories.

### TTL policy (set at insert)
| Category | TTL |
|---|---|
| `allergy`, `condition` | NULL (never decay) |
| `medication` (active) | NULL (never decay; `status='historical'` already handles old meds) |
| `lab_result` | 365 days |
| `appointment` | 90 days past `valid_from` |
| `provider`, `insurance`, `financial`, `family`, `legal` | NULL |
| `emotional_state`, `preference`, `lifestyle`, `treatment_response` | 180 days |
| `other` | 90 days |

### File touchpoints
- `apps/web/src/lib/memory/validators.ts` — add `decayForCategory(category, status, polarity): Date | null`
- `apps/web/src/lib/memory/extract.ts` — populate `decay_at` on INSERT
- `apps/web/src/app/api/cron/memory-decay/route.ts` — new cron handler (Bearer = `CRON_SECRET`)
- `vercel.json` — add cron entry: `{ "path": "/api/cron/memory-decay", "schedule": "0 3 * * *" }`
- Tests: `__tests__/memory-decay.test.ts`

### TDD
1. `decayForCategory('allergy', ...)` → null
2. `decayForCategory('lab_result', ...)` → +365d
3. Cron handler with valid Bearer → soft-deletes expired rows
4. Cron handler with invalid Bearer → 401
5. Cron handler does NOT touch `valid_to IS NOT NULL` rows (already soft-deleted)
6. Cron handler is idempotent (running twice same minute = same end state)

### Rollback
Revert + remove cron entry from vercel.json. Existing `decay_at` values stay (harmless — no reader without the cron).

## Chunk 3 — Summaries as memory tier

### Goal
Embed `conversation_summaries.summary` on write. At retrieve time, union top-2 nearest summaries into the candidate set with a score multiplier of 0.7.

### Why 0.7
Summaries are coarser than individual memories — high recall but lower precision per-token. 0.7 multiplier prevents them from crowding out high-importance tier-1 facts but still surfaces relevant past-conversation context.

### File touchpoints
- `apps/web/src/lib/memory/extract.ts` — `summarizeConversation` already inserts; add embedding via `embedTextBatch` before insert.
- `apps/web/src/lib/memory/retrieve.ts` — extend hybrid CTE with `UNION ALL` branch from `conversation_summaries`.
- Backfill script: `apps/web/scripts/backfill-summary-embeddings.ts` for any rows inserted pre-chunk-3.
- Tests: `__tests__/summary-retrieval.test.ts`

### TDD
1. `summarizeConversation` saves summary WITH embedding (not null)
2. `loadRelevantMemories` returns 2 summaries when present, multiplied by 0.7
3. Tier-1 facts (importance >= 0.9) never displaced by summary in top-K
4. No summaries for user → query still works, returns memories only
5. Backfill script embeds missing rows, idempotent on re-run

### Rollback
- Drop the UNION branch in `retrieve.ts` — summaries simply stop appearing in results.
- Embedding column populated rows are harmless if unused.

## Chunk 4 — Temporal contradiction handler

### Goal
Replace the destructive `[SUPERSEDED by: ...]` fact-mutation with a non-destructive close-old/insert-new pattern that preserves the original fact for audit.

### Current (destructive)
```ts
// resolveConflicts in memory-conflict.ts
await db.update(memories)
  .set({
    confidence: 'low',
    fact: `[SUPERSEDED by: "${newFact.slice(0, 100)}"] ${mem.fact}`,
  })
  .where(eq(memories.id, mem.id))
```

### New (audit-preserving)
On detected contradiction (same `user_id` + `category` + opposite polarity OR same medication name + different dose):
1. Generate rewritten narrative via Haiku: "Eleanor was on Tamoxifen 10mg (until 2026-04), now on Tamoxifen 20mg"
2. INSERT new row with rewritten narrative, `status='active'`, `polarity='asserted'`, references original via `superseded_from_id` (new column or via a JSON metadata field)
3. UPDATE old row: `valid_to = NOW()`, `status = 'historical'`. **DO NOT mutate `fact`.**

### Conflict detection
- Same `user_id` + `category` + opposite `polarity` (e.g. "denies penicillin allergy" → "is allergic to penicillin")
- Same `user_id` + `category='medication'` + same medication name (regex) + different dose

### File touchpoints
- `apps/web/src/lib/memory-conflict.ts` — replace conflict-path logic; add `rewriteContradictionViaHaiku`
- `apps/web/src/lib/memory/extract.ts` — passes new fact through new flow
- Possible schema add: `memories.superseded_from_id uuid REFERENCES memories(id)` for audit chain — defer unless tests force it
- Tests: extend `memory-conflict.test.ts`

### TDD
1. Conflict detected → old row `valid_to` set, `fact` unchanged
2. Conflict detected → new row inserted with rewritten narrative
3. No-conflict → no UPDATE, no rewrite call (cost guard)
4. Same-med different-dose → rewritten narrative includes both doses
5. Haiku failure → fall back to old behavior (insert new + close old with raw fact, skip narrative)
6. Retrieval excludes `valid_to IS NOT NULL` rows (already true via memory-v2 query — assert)

### Rollback
Revert; old destructive path returns. Rows closed via `valid_to` stay closed (harmless — old rows are no longer mutated, just hidden).

## Chunk 8 — ConvoMem for users with <30 sessions

### Goal
For users with fewer than 30 lifetime sessions, replace the L4 hybrid-retrieval block with the last N raw messages (where N is computed from daily token budget).

### Why
Hybrid retrieval needs corpus density to outperform raw context. New users have <30 sessions → near-empty memory pool → retrieval mostly returns garbage. Raw recent messages outperform empty/noisy retrieval.

### Dev-testing concern (you flagged it)
Today, **every user has <30 sessions** → ConvoMem mode would be the only path
exercised. Hybrid retrieval would never run in dev.

**Resolution:** add `FORCE_HYBRID_USER_IDS` env var (comma-separated UUIDs).
For testing accounts in that list, hybrid retrieval runs regardless of session count.

### Session counting
- `conversation_summaries` rows already serve as a session marker (one summary
  per session boundary). Count rows where `user_id = $1` as session count.
- Cheap query; cache in request scope.

### File touchpoints
- `apps/web/src/lib/memory/retrieve.ts` — add `loadConvoMem(userId, limit)` branch
- Caller (`chat` route) — switch on `sessionCount < 30 && !forceHybrid`
- Tests: `__tests__/convomem.test.ts`

### TDD
1. User with 0 sessions → ConvoMem branch
2. User with 29 sessions → ConvoMem branch
3. User with 30 sessions → hybrid branch
4. User in `FORCE_HYBRID_USER_IDS` with 0 sessions → hybrid branch (dev override)
5. ConvoMem returns last N raw messages, N computed from budget
6. ConvoMem keeps tier-1 facts (allergies, active medications) in context even when bypassing hybrid

### Rollback
Set env var to a sentinel like `*` to force hybrid for everyone; or revert.
